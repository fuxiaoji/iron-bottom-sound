用户 2026-09-18 明确要求：工作时可以建立子 agent 分配任务，**用 glm4.7 / glm4.6v 等免费模型**处理轻量工作；困难工作也可以用复杂模型建立**多 agent 协作**；但**主 agent 必须审计其产出**。

**Why**：论文流水线里既有大量机械劳动（格式转换、词数统计、批量文件扫描、提示词模板套用、引用字段比对），也有少数需要判断力的工作（定理推导、证据-主张一致性裁定、PIVOT/REFINE 决策）。把前者交给便宜模型能省成本和时间，但**子 agent 没有任何"真实性"负担**——它最容易犯的恰恰是本项目最致命的错：编造数字、编造文献、把未运行的实验报告为已运行、把失败分支写成通过。`RESTRICTS.yaml` §5 把这类问题定为 CRITICAL FABRICATION，所以**未经审计的子 agent 产出一律不得进入论文、结果或台账**。

**How to apply**：

1. **可委派（低风险，适合免费模型）**：只读检索与定位、文件清单/词数/字段统计、格式转换、提示词模板实例化填空、批量文本抽取。共同点：**产出可被主 agent 用一条命令或一次文件比对独立复现**。
2. **不可委派（高风险，必须主 agent 亲做或复杂模型多 agent 交叉）**：任何进入论文的**数值**、任何**文献条目**、任何**结论性判断**（PROCEED/REFINE/PIVOT、门控 verdict）、任何**定理与证明**。
3. **审计动作（每次委派必做，不得跳过）**：
   - 要求子 agent **返回可核查的原始产物路径或命令输出**，不接受只给结论；
   - 主 agent 亲自**重跑或抽样复核**关键数字（如重新统计词数、重新 `grep` 计数、重新解析 JSON）；
   - 与既有冻结证据（`research/final_v14/` 的 freeze/hash 文件）比对，任何不一致都要追到差异来源；
   - 审计结果与**未通过项**一并写入 `havedone.md`；**不得只记录通过的部分**。
4. **出处纪律**：子 agent 引用的每条文献必须保留原始 `cite_key` 与 DOI，主 agent 按 `RESTRICTS.yaml` §5 `literature_fidelity` 复核，无法溯源的一律剔除。
5. **隔离要求**：阶段 14（结果分析）与阶段 24（第三方评审）按原文要求必须使用**独立上下文**，不得把主 agent 的既有结论喂进去诱导其附和。

**当前可用性**：见 [[agent-delegation-environment]] —— GLM 路由尚未配置，所以现阶段"用免费模型跑子 agent"还**不具备执行条件**。在用户给出 GLM 端点与 key 之前，委派只能走 ZCode 内置的 `Explore` / `general-purpose`，其模型由会话配置决定；此时更应严格执行上面的审计动作，因为无法用"模型便宜所以出错可以原谅"来降低审计标准。

# 夜间发现与识别分层（2026-10-13）

用户授权的历史补充，规则标识 `IBS-R-NIGHT-ID`。用户确认识别后显示**舰名和舰型**，以便兵棋操作；最新算子要求是目视接触和雷达接触统一使用 `敌舰.png`，不使用 `隐藏.png`。此补充不填补萨沃岛/塔萨法隆格原典部署、地形或舰卡的未决缺项。

## 原典与历史依据的边界

中文规则 PDF 第13页9.2规定雷达视全地图舰只为可见，但目标在陆面4格内或岛屿处于两舰之间时除外；9.3规定照明弹提前一回合计划、移动后检定、中心2格、炮击后移除；9.4规定探照灯范围和开灯舰暴露。原典没有提供“发现但不能识别”的统一距离。因此不能把新增识别阈值写成9.2–9.4原典数值。

美国海军情报局的[《萨沃岛战斗叙事》（1943；海军历史部门重刊）](https://www.history.navy.mil/content/dam/nhhc/browse-by-topic/War%20and%20Conflict/WWII-Pacific-Battles/Savo%20Web.pdf)记录帕特森号取得约8000码雷达接触；接近到约3000码时仍未确认来舰身份，挑战信号未获回应，使用探照灯、交火后才认出来舰像芝加哥号。这个实例支持发现与确认身份可以分离，也说明照明本身不是现实中百分之百可靠的舰名识别。

[《瓜达尔卡纳尔战斗叙事》](https://www.history.navy.mil/content/history/nhhc/research/library/online-reading-room/title-list-alphabetically/b/battle-of-guadalcanal.html)记录远距离雷达接触、岛屿干扰，以及目视报告只能区分大舰可能为战列舰/巡洋舰的情况。识别受到距离、雨、背景、观察训练和敌我信号影响，史料不能证明所有舰都有相同识别距离。

本补充选用 **3格（每格600码，约1800码）** 作为保守的、可调整的游戏参数，不声称史料保证此距离准确识别。照明识别和显示完整舰名是用户要求的操作简化。阈值保存在结构化 YAML，并在创建对局时冻结到规则快照；UI、API和LLM不复制这个常量。

## 可执行行为

|状态/条件|玩家能看到的内容|算子|
|---|---|---|
|未发现|没有舰船实体、位置或真实编号|不显示|
|目视或雷达发现，未识别|接触代号、位置、可观察的航向/速度，允许对接触下令|敌舰.png|
|未照明且在3格内、当前视程内，光学视线通畅|舰名、舰型；其他损伤字段仍遵守原隐藏战损规则|用户提供的国家/舰种算子，缺少对应种类时沿用原命名算子|
|有效探照灯或生效照明弹照亮且有光学视线|舰名、舰型|同上|
|仅雷达发现|全图接触能力，岸边4格和岛屿遮挡例外；雷达本身不识别|敌舰.png，加蓝色虚线圈|
|身份已识别且持续跟踪|熄灯后保留身份|同上|
|失去接触后远距离重新发现|需要重新识别；记忆中旧身份带时间，不当作当前真值|敌舰.png|

雨区和陆地阻挡照明识别，雷达失效仍按原典；照明弹的2格半径、检定及持续时间不变。探照灯沿舰至目标画直线，照明源使用 `光源.png`。玩家仍可合法给同一目标多束灯；状态机优先协调一束灯支持现有射击，避免重复照亮同一目标。

## 接口与信息隔离

每个对手舰使用对局私有盐和观察方派生的稳定接触编号。识别后编号不变，只有标签和算子改变。接触编号不含真实舰名、国家或原始舰船ID；私有盐不出现在玩家响应、DOM或模型提示。

观察、合法行动、炮击/鱼雷辅助、照明预览、事件、记忆和模型输入统一投影。未知目标不下发舰型、装甲、船体、VP、炮位和发射器，也不按其真实武器生成射界热力或AI移动预测。未知舰型的炮击修正仅显示可见项估算，实际裁决仍由引擎完整执行。真实编号不能绕过接触目标检查。

事件保存发生时的身份知识，后续识别不会使旧日志重新透露当时不知道的舰名或火力资料。照明预览只画草稿效果，不执行识别。Command Delay的舰队视图和编队视图分别使用搭载编队/本地观察员，不借全局观察识别远处目标。

已有存档缺少 `night_recognition` 开关时按关闭处理，规则快照与历史保留；新API创建的夜战局默认开启。源程序内的测试/基准配置仍可显式关闭。保存/导入副本保留接触代号与快照，权威回放使用封存的真实命令。

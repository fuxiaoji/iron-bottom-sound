# 八区间移动与鱼雷接触（IBS-R-06-GC8）

来源：中文规则 PDF 第14页 Greg Courter 分段表，原件逐格目视核验。
唯一执行数据：`resources/derived/structured/rules/movement-impulses.yaml`。
`greg-courter-8-v1` 新局采用下表；每回合固定8个区间，数字为消耗1 MF的区间。

| 本回合MF/雷速 | 消耗MF的区间 |
|---|---|
| 0 | 无 |
| 1 | 4 |
| 2 | 3、6 |
| 3 | 2、5、8 |
| 4 | 2、4、6、8 |
| 5 | 1、2、4、6、8 |
| 6 | 1、2、4、6、7、8 |
| 7 | 1、2、3、4、6、7、8 |
| 8 | 1、2、3、4、5、6、7、8 |

用户2026-10-21裁定：速度3末段印刷S按M处理（IBS-Q-008）；途中发射使用实际发射区间后的剩余时间（IBS-Q-009）。这些裁定明确记在数据中，原PDF不改。

舰船的移动程序仍以MF书写，120度转向的付费MF在对应区间原地消耗；隐蔽接触标记使用同一时钟。鱼雷速度周期按回合年龄选行，射程按实际走过的格数减少。

## 途中发射

`launch_at_mf` 保持现有订单格式。引擎由本方已封存移动程序的总MF和发射MF，查表得到实际发射区间。舰船完成该区间动作后发射，新雷在此区间不再前进，只在雷速行中后续的M区间走格；后续回合恢复完整速度行。

例如4 MF舰的第2 MF在区间4完成，随后发射8速雷，本回合仅在5、6、7、8前进，共4格；第4 MF在区间8发射则当回合不前进。不会补足旧算法的“雷速减已用MF”，也不额外插入子步。发射记录保留MF、实际区间及当回合剩余移动区间。

## 接触与结算

每区间先计算各舰及雷的动作，再检测同格、对向交换相邻格；同向尾随经过对方刚离开的格子不构成接触。已用完本回合移动次数但仍有射程的雷停在原格，舰船随后进入仍能接触。射程最后一格先检查接触，再移除耗尽且未接触的雷；撞陆地/出地图立即移除。

新时钟允许击中友舰，排除发射舰自身及发射时与发射舰共格的目标。第一次接触后停止该齐射，内部冻结目标当时的位置、航向、速度、区间和接触类型。炮击阶段之后再按冻结航向/速度算鱼雷命中、对当前舰体施加损伤；整批齐射在命中检定后移除。内部快照不进入任何一方观察接口。

## 状态机与兼容

基础战术、鱼雷专门战术、真实编队及其训练profile共用引擎的时间表：友舰航路按8段对齐；避雷比较本方候选航路和本方观察中可见雷的同区间位置/对穿；鱼雷拦截和航路压制使用实际发射区间。假设敌方航路仅由公开位置/航速生成，不读取敌方封存订单。完整射程几何线仍可作为保守的友舰发射安全筛选，不能视为实际同区间命中。

新建局及首条game_created标记版本；旧存档/事件缺版本字段时仍按`legacy-mf-v1`执行，旧事件不追加新字段。历史世界杯、正常赛果、旧封存订单和原来源文件不迁移。新旧时钟分别有确定性回放测试，避免更新后重算历史成绩。

边界测试：`tests/test_movement_impulses.py`；既有引擎、鱼雷辅助、战术与真实编队、API存档、整局与回放回归继续适用。

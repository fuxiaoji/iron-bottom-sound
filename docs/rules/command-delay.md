# 《铁底湾的回响 IV》命令延迟模式玩家规则

版本：命令延迟扩展 v2.2　　适用想定：`SUPPORTED_SCENARIOS` 白名单内的全部 16 个想定（含第二次马里亚纳海战（二马）`IBS-S-EM-01` 与虚构想定 `IBS-S-FM-01`）；自定义想定不可用本模式

> “命令延迟模式”是本项目在真实模式编队指挥链之上增加的**新模式**，用于表现舰队总指挥与编队指挥官之间的通信延迟、任务式命令与本地自主。它**不改变**经典模式，也**不改变**真实模式既有的通信与观察语义。

## 一、三个互斥入口

| 入口 | `realistic_command` | `command_delay_mode` |
|---|---|---|
| 经典（Classic） | 关 | 关 |
| 真实（Realistic） | 开 | 关 |
| 命令延迟（Command Delay） | 开 | 开 |

命令延迟模式**必须**运行在真实模式的编队核心之上。若请求 `command_delay_mode=开` 而 `realistic_command=关`，建局直接失败并说明原因，系统**不会**替你自动打开真实模式。

在不支持该模式的想定上开命令延迟同样会失败。经典与真实模式下，游戏不产生任何命令延迟状态。

## 二、编队机动方式（IBS-R-RC-08）

真实模式与命令延迟模式都有两种编队机动方式，**默认是尾随（FOLLOW_WAKE）**，与既有真实模式行为完全一致。

### 尾随 FOLLOW_WAKE（默认）
领舰先走，后舰依次到达前舰转向点后再转，即 successive / follow-the-leader。既有真实模式的共用航速、脱队、旗舰继承规则照常适用。

### 整队机动 MOVE_TOGETHER（可选）
“各舰同时转向、同时前进”，不复制领舰经过的格位。资格条件（全部满足才可执行）：

1. 全部在编成员位于同一条六角直线上；
2. 间距统一；
3. 当前同航向；
4. 共同航速交集非空；
5. 无指挥中断；
6. 同一个领舰机动方案施加到每舰自身位置后全部合法；
7. 整批次的同脉冲同格/换位检定通过。

执行方式：每个全局 MF 脉冲，所有舰执行与领舰**相同的机动指令记号**；`advance` 时各舰沿自身当前航向前进，`turn` 时各舰在同一脉冲同向转向。

**重要**：同时转向只旋转航向，不旋转舰列轴线。因此整队机动后编队可能由纵队（COLUMN）变成横队/斜队（STRAIGHT_LINE）。系统会如实记录 `geometry_kind`，**不会**继续把它当纵队。

要切回尾随，必须先执行**重整纵队（REFORM_COLUMN）**：本回合继续整队机动，且只有在回合结束时确实与纵队轴线对齐，才恢复 `FOLLOW_WAKE`；没有对齐时系统记录“重整被拒绝”，编队保持斜队，不能假装纵队已恢复。

## 三、通信处理链（IBS-R-CD-03）

本模式**不**模拟无线电传播。在一个 3 分钟回合的尺度上，传播时间在地图任何距离上都等于零；真正造成延迟的是人工作业与流程：

```text
指挥决策 → 拟稿/制式信号 → 加密/编码 → 发送 → 转报/再加密
        → 抄收/转录 → 译码/解释 → 消息中心/CIC/舰桥分发 → 确认/澄清 → 执行
```

TBS 短语音可绕过大部分密码与消息中心流程，因此**可能在同一回合内送达并确认**；编码 W/T、跨密码体系转发、中继、视觉信号逐舰下传、收报后译码都会增加真实处理延迟。

| medium | 含义 | 抽象回合开销 |
|---|---|---|
| TBS_SHORT | 短距战术（视距内、战术范围内） | 0；复杂任务修正案可 +1 |
| BLINKER | 直接视觉/逐舰重复下传 | 0 或 +1，每个中继级 +1（有上限） |
| WT_CODED | 编码无线电报经消息中心 | +1 |
| WT_REENCIPHER_RELAY | 转报/再加密 | 在编码基础上再 +1 |
| MULTI_HOP | 复合路由 | 合计可达 t+2 |
| BLACKOUT | 无可用通路 | 不发送 |
| —（当面） | 总指挥与受令编队同队：当面交办 | 0，且不占用信道容量 |

**当面交办是唯一不受通信链路约束的下令方式**：总指挥所在编队的指挥当面受令，同一回合即可执行；该次交办仍会写入报文台账（注明“同编队当面下令”），因为台账记录的是**说过什么**，不只是**发了什么**。

**距离只决定用哪种媒介，不换算成回合延迟。** 直连 TBS 的范围使用想定自身给出的视距，不额外发明第二个射程常量。

以上回合值全部标注为 **SIMULATION_ABSTRACTION**：它们受史实约束，但**不是**“历史实测平均值”。本模式**不定义**任何丢包率或错码率；`p_drop` / `p_garble` 只作为后续科研模式的接口存在，且必须附带来源才允许生效。

## 四、通信拥塞（IBS-R-CD-05）

每条信道每回合有固定容量。超容量时：高优先级先发（URGENT > OPERATIONAL > ROUTINE），同级按发出顺序；等待超过 TTL（默认 3 回合）的报文被丢弃并记录原因。全程确定性、可解释，不含随机数。

## 五、任务式命令（IBS-R-CD-04）

上级下达的是**任务式命令**，不是逐回合微操：

```text
任务 MISSION（做什么＋为什么）
意图 COMMANDER INTENT
编队任务 TASK
协同措施 COORDINATION
作战区域 / 航路点 / 期限
目标优先级 TARGET PRIORITY（只给权重，炮位分配仍由引擎选择器完成）
交火规则 ROE / 火力限制
风险与保舰约束
报告要求
通信计划
失联预案 LOSS OF COMM
会合点 RENDEZVOUS
有效起止
```

要点：**目标优先级只改变选择器的偏好，绝不改变合法性、射界、命中或修正规则**；指定重点目标当前不可见/不可射时，选择器自动回退到其余合法目标。子指挥官自行决定“怎么做”，除非协同必需。

### 三类备选方案（绝不写成任意 if/else）

- **EXPLICIT_SIGNAL_BRANCH**：事先写好，只有收到指定信号才启用；
- **LOCAL_CONDITION_BRANCH**：上级事先授权，本地可验证条件满足时自动启用（例如遭遇优势之敌 → 跟踪、报告、避免决战）；
- **LOSS_OF_COMM_BRANCH**：失联后继续任务、按时间地点会合、失去最低能力则撤退、可通信时报告。

命令未覆盖的新情况，编队指挥官可按上级意图自主选择最有利于总体任务的局部任务，并在恢复通信后发出**偏离报告**（说明其与 intent 的一致性）。

## 五之二、指挥链：总指挥与分舰队指挥（IBS-R-CD-09）

```text
舰队总指挥（独立 agent，自己的记忆与视野）
  ├─ 当面下令 ──→ 本队编队指挥（同回合生效）
  └─ 电报下令 ──→ 其余编队指挥（按媒介与队列延迟送达）
分舰队指挥（每个编队一个 agent，自己的记忆与本地视野）
  └─ 每回合上报 ──→ 舰队总指挥（引擎保底态势 + 目击，加上它自己写的一句判断）
```

要点：

- **总指挥的态势几乎全部来自报告**，而报告是**按发出时刻**计龄的：它命令时依据的往往是几回合前的图。总指挥可以本回合不下令（`no_order`），避免微操。
- **上报是双向链路的回程**：引擎保底给出结构化态势与目击（编队从不“忘记上报”），编队代理在此之上写自己的判断（看到什么、是否偏离命令）。上报走与命令相同的媒介与队列，因此会迟到、会排队、会过期。
- 编队的**确认**（ACK）、**偏离报告**（DEVIATION_REPORT）与**澄清请求**（CLARIFICATION_REQUEST）都是真实报文，占用信道并可能迟到；台账会记录确认落地的回合。
- 一次交手（DESRON 的整队齐射）中，护航分队受命护卫、主力分队受命压制，两者都可能因延迟而按旧图行动——这正是本模式要表现的东西。

## 五之三、界面怎么用（一个回合的操作顺序）

左侧栏顶部的「下达命令」面板就是总指挥的全部操作台，按四步走：

1. **写命令** —— 在「收件编队」里选一个编队（点「指挥链与通信」里的编队卡片也可以），在「命令正文」里用自然语言写清楚你要它做什么。正文是权威内容：引擎读到什么，编队代理就读到什么。不想自己组织语言时，用「快速套用」挑一个任务模板，或用「逐项辅助」把约束、火力优先级与完成期限补进正文。
2. **发电报** —— 按下之前，面板会先告诉你这条命令**现在发出去会怎样**：当面交办（本回合生效）、TBS 直连（本回合投递）、还是编码电文（链路开销 +1 回合）；同时给出距离、TBS 射程与是否因正文过长而占用多个时隙。命令是一项**信号**：送达之前，那个编队仍按它手上的旧命令行动。与它现行命令措辞相同的话，引擎会记为「重复命令」而不新建修订，界面会先提醒你。
3. **看代理方案** —— 「本阶段各编队的代理方案」列出每个编队代理本回合自己选定的机动方案与预案分支。命令延迟模式里你不必逐舰填表：这一栏就是它们交上来的作业。
4. **校验、封存并交接** —— 把本侧订单交出去并推进裁决。命令延迟模式下，本侧订单**取各编队代理选定的方案**（不是状态机自动填的那一份）；只有你在「高级：手写完整 OrderBatch」里亲手改过 JSON 时，才以你改的为准。

关于模型：编队代理默认按**确定性教条**行动。要让它调用模型，在「指挥链与通信 → 编队代理」里接入密钥（可只给本侧）；密钥只留在服务进程内存，服务重启后需要重新接入。接入后，各编队会在下一次推进阶段时请求模型给出方案；界面上标「教条」的地方，就是引擎如实告诉你这些决策不是模型做出的。

## 六、指挥官自主权次序（IBS-R-CD-02）

```text
1 引擎合法性
2 最新有效命令
3 上级意图
4 协同约束
5 已授权备选方案
6 本地战术最优化
7 仅在任务与风险约束内保全兵力
8 恢复通信后报告偏离
```

舰队总指挥与编队指挥官的权限状态可查：`FLEET_DIRECTED`（总指挥所在编队）、`DELEGATED`（受领任务、本地执行）、`LOCAL_AUTONOMY`（失联回退）。链路状态 `DIRECT / RELAYED / STALE / BLACKOUT` 由**实际收到报文的新鲜度**决定——只能靠真正收到通信而改善。

## 七、观察与信息边界

- **舰队总指挥视图**：只有总指挥**所在编队**是精确状态；其余本方编队一律以“报告”形式呈现（引导舰位置/航向/航速/舰数/几何），并带报告回合与年龄。敌方编队**从不**出现在舰队视图中。
- **编队本地视图**：只包含本编队自身状态、本地地图、**本编队自身舰只**能看到的接触、生效命令、已收报文、通信状态、外部陈旧报告、合法编队动作清单、合法目标优先级选项、允许的报告动作。
- 本地代理**看不到**本方全局真值。
- **上报正文的边界**：编队代理写给总指挥的正文只能提到**该编队自己目视过的**敌舰；审计按此判据检查（越界的提及会被判为“向上泄露”）。
- **记忆预算**：每个指挥 agent 保留同类条目 48 条、备忘 24 条、单条 600 字、渲染上限 12000 字；超限时先裁最旧的历史，**当前命令与备忘必须保留**。

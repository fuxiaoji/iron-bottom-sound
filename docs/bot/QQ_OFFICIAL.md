### LLM 参谋与自然语言下令

群内真正 @机器人，或在已绑定的私聊中发送：

```text
/参谋 [对局ID] [问题]
/下令 [对局ID] 本阶段的自然语言命令
/帮助 LLM
```

`/参谋` 调用 DeepSeek 汇报已知战况和最多三条建议，不修改对局。群内 PVE 使用唯一玩家的受限观察，PVP 只使用双方公共交集；私聊可分析本人的完整受限观察。群旁观者可查看群公开战报，有多局时须明确 ID。

`/下令` 仅控制发消息者已拥有的席位，群内直接使用已验签 member 身份，不要求额外私聊绑定。模型将明确的舰船、动作和目标转成 OrderBatch，原引擎再校验当前版本并提交；思考期间版本改变、越权、未知字段、非法命令或模糊意图均不推进。每条只提交一个阶段，不启动连续自主对战。炮战示例：`/下令 所有可开火炮位各自射击射界内最近的已发现敌舰，同距按候选顺序选择，不使用鱼雷、烟幕或照明`。需要时改用具体舰名、炮位和已发现目标，以减少歧义。

群内 PVP 回执只显示封存/阶段进度与公共图，不转发看过本方信息的模型文本；澄清也不回显私有单位或计划。PVE 与私聊回执显示动作种类/数量、原引擎战况与图。建议只是模型判断，实际合法性与战果以引擎为准；只请求建议不会偷偷变成自动下令。

模型只接收显式白名单观察、合法行动与 OrderBatch schema，不接收群/成员/私聊身份、原始世界状态、PRNG、对手秘密订单或凭据。网络调用在 SQLite/引擎锁外；保存 pending/prepared/done 以避免同事件重复计费和推进。已完成回执和 prepared 订单可重启恢复；中断的 pending 不自动重发，需查询后发新指令。最多同群 2 个处理中请求、单人同群每分钟 6 条；每次一个 HTTP 请求、不自动重试，默认 45 秒超时，拒绝截断/过大/非法结构。

服务器专属配置示例（密钥只放服务器私有环境文件，不入聊天或 Git）：

```dotenv
IBS_BOT_LLM_PROVIDER=deepseek
IBS_BOT_LLM_MODEL=deepseek-flash
IBS_BOT_LLM_API_KEY=replace-with-private-api-key
IBS_BOT_LLM_TIMEOUT=45
IBS_BOT_LLM_MAX_TOKENS=2400
```

省略模型时 Bot 默认 `deepseek-flash`，普通 API endpoint 为 `https://api.deepseek.com`，DeepSeek 请求显式关闭 thinking。空密钥会禁用 LLM 命令，其他功能继续可用；不借用视频、Coding Plan 或其他项目凭据。使用单次 `chat/completions` 与 JSON 模式，字段依据 [DeepSeek官方API](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON模式](https://api-docs.deepseek.com/guides/json_mode/)；账户模型枚举已实际验证。另支持专属 `zhipu`/`compatible` 配置，未经本次真实调用验收。

### 管理员 LLM 裁判

在群里真正 @机器人，再发送 `/裁判 自然语言`；已有多局时使用 `/裁判 对局ID 自然语言`。也可在已绑定且能明确目标群的私聊使用。示例：

```text
/裁判 创建一个编队模式人机对局，我执盟军
/裁判 对局ID 推进一个阶段
/裁判 对局ID 把标枪的位置修正为P15，航向向南
/裁判 对局ID 撤销刚才一步
/裁判 对局ID 解释当前阶段，不修改
/帮助 裁判
```

裁判使用同一专属 DeepSeek API，管理范围由服务端授予。`IBS_BOT_REFEREE_ADMINS` 必须是已验签的当前 App 群成员身份的 JSON 数组，默认 `[]` 不授予权限；不能填 QQ 数字账号或从自然语言中自称管理员。已绑定 C2C 只通过原别名解析到同一群身份；权限每次执行前再次检查。生产配置保存在私有环境文件，公开仓库不存真实管理员身份。

- 创建：普通/编队、PVE/PVP、想定、阵营、seed，仍走原建局接口，席位固定当前管理员；默认编队/PVE/IBS-S-03/盟军/seed1。
- 推进：一次1至6个决策阶段，保留双方已有封存订单，缺失方由现有离线状态机补齐，再由原引擎结算。这包含管理员推进 PVP 双方的权限；每条请求结束即停止，不是后台持续运行，也不表示 LLM 制定双方战术。
- 修正：坐标、航向、速度、正舰体值、损伤/火灾/计时器、已有炮位和鱼雷发射器的运行状态，以及回合/阶段/可见度/比分等进度字段。必须有完整值并通过当前地图、原容量、类型及引用校验；未见的目标须由用户明确完整点名，模型不能猜隐藏舰ID。
- 撤销：每次保存变更先保存私有完整状态快照，包括 RNG。撤销最近可用快照时恢复状态并增加版本号；不回退身份或席位，不编造启用快照前的旧历史。创建后可以撤销后续状态修改，不能通过撤销删除新对局。

当前不直接修改需要跨结构同步的沉没/复活、撤退、增援入场、编队归属生命周期字段；相应请求会拒绝或要求澄清。舰船原始身份/来源/能力、规则、任意文件、服务器账号和凭据均不在裁判状态修正接口内。强制修正阶段或回合会清除旧阶段订单，需按新版本重新下令。修改结果以服务端实际回执和回图为准，模型不能仅靠一句“修改成功”改变存档。

模型上下文仍受限：PVE只取玩家观察，PVP取公共交集，不提供全图、秘密订单、成员身份或 RNG。私有 SQLite 存请求哈希、结构化操作和快照；模型 I/O 不持写锁。模型返回后校验冻结版本，失败整批回滚；相同请求的 pending/prepared/done 防止重复调用和重复执行。创建收据已提交而最终回执中断时，复用原收据恢复，不再建第二局。修改后的群图使用既有公开投影。

群聊预设的“我的对局”和私聊预设的“自动”位置改为“裁判”；旧指令仍可直接输入。平台每场景10条上限没有改变。

`/帮助` 为快速入口；专题 `/帮助 快速开始`、`/帮助 推进`、`/帮助 手动`、`/帮助 PVP`、`/帮助 绑定` 解释绑定、双方封存、自己下令及旧完整格式。斜杠与旧「铁底湾」前缀均兼容。

### 手动选择、检查与提交

1. 私聊 `/行动` 读取当前阶段，每页最多 6 个中文候选；按回复中的下一页命令翻页，也可按本方舰名、舰 ID 或编队 ID 筛选。
2. 复制候选页的 `/选择 版本号 行动编号 对局ID`，将一个动作加入草稿。可以重复选择其他舰船/武器；同一单位/武器的后选动作替换前选动作。
3. `/草稿` 检查所有已选动作；超过 6 项可翻页。`/清空 版本号 对局ID` 只清除草稿。选择、查看与清空都不推进阶段。
4. `/提交 版本号 对局ID` 将整个草稿交给原引擎校验。未选单位不会由状态机补齐，缺少必需单位或组合不合法会拒绝提交。允许不行动的阶段，也必须明确选择已校验的“不行动”项。

草稿按用户席位、群、对局、版本与阶段隔离，持久保存在服务器私有数据库。候选来自本方受限观察与引擎 `legal_actions` 提示，代表菜单不穷举合法行动空间：编队部署目前提供默认部署，编队移动提供可达领舰路径；自定义重组、夜间照明/烟幕、接触部署，以及更细的增援航向/速度仍须高级 JSON 或 MCP。动作选择不等于完整组合已合法，最终由原引擎裁决。版本过期时重新查询；重复事件和重复提交不会再次推进。

控制台私聊预设为 10 项：帮助、参谋、态势、下一步、行动、提交、裁判、下令、选择、草稿；底部菜单保留帮助、态势、下一步。`/我的对局`、`/清空`、`/建议` 与 `/确认` 仍可直接输入，未占原生面板名额。当前配置收据见 [qq-referee-panel.json](evidence/qq-referee-panel.json)。

### 完整格式与首次绑定

以下流程要求真实群已在 OpenID 白名单内。群命令均需真实 @ 当前机器人。

1. 在群中创建或加入，创建者占所选一方，PVP 另一人加入另一方：

   ```text

   @铁底湾指挥官 铁底湾 创建 编队 pve IBS-S-03 日军
   @铁底湾指挥官 铁底湾 加入 对局ID
   ```

   可省略「铁底湾」前缀，也支持「创建 编队pve」「创建 普通PVP」这种模式与对手连写；想定和阵营仍按上面的空格分隔。

2. 保存回复中的真实群 OpenID 和对局ID，私聊机器人申请自己实际席位的绑定：

   ```text
   铁底湾 群openid 对局ID 绑定 盟军
   铁底湾 群openid 对局ID 绑定 日军
   ```

3. 绑定码只在私聊返回；该席位本人到对应群确认：

   ```text
   @铁底湾指挥官 铁底湾 绑定 私聊获得的验证码
   ```

4. 绑定成功后私聊查看本方图、合法行动，再提交本阶段命令：

   ```text
   铁底湾 群openid 对局ID 态势
   铁底湾 群openid 对局ID 行动
   铁底湾 群openid 对局ID 行动 舰ID
   铁底湾 群openid 对局ID 建议
   铁底湾 群openid 对局ID 自动 版本号
   铁底湾 群openid 对局ID 确认 版本号
   铁底湾 群openid 对局ID 提交 版本号 {"side":"allies","phase":"reinforcement"}
   ```

「态势」返回当前版本、阶段、战况与本方 PNG；「自动」明确使用状态机建议并返回本方 PNG；「建议」不会提交。版本号来自最新态势。高级手动 `orders` 为引擎 OrderBatch 对象，完整 schema 可由 MCP `ibs_legal` 获取。普通模式逐舰下令，编队模式先部署，再用 `formation_movement` 等字段。「确认」为空命令，只有引擎认可时才通过。

PVP 双方使用相同阶段版本；第一方封存后等待，第二方完成后统一推进。另一方须重新私聊「态势」查询结果，不等待异步通知。群公共图也主动查询：

```text
@铁底湾指挥官 铁底湾 战况 对局ID
@铁底湾指挥官 铁底湾 状态 对局ID
```

PVE 群图显示唯一人类席位的玩家观察，并在标题标注阵营：本方船和玩家已发现的敌舰可见，未发现敌舰不补入，未识别目标显示“敌舰”。图像不包含私有命令、编队计划或隐藏能力。PVP 仍使用双方观察交集；没有共同可见舰船时图上提示私聊查看本方态势。群中发「态势/行动/选择/草稿/提交」会提示改用私聊。来源不完整而被引擎阻断的想定仍保持阻断，不由机器人补造规则。

## 身份域与 MCP

官方群事件使用 `author.member_openid`，C2C 使用 `author.user_openid`。同一 AppID 下同一用户跨群的 member OpenID 也不同，不把两个字段、数字 QQ 号或相同原始字符串自动合并，见 [唯一身份机制](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/dev-prepare/unique-id.md) 与 [事件字段](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/event.md)。服务使用：

```text
群席位：qqbot:1905878837:member:群openid:member_openid
私聊：  qqbot:1905878837:c2c:user_openid
房间：  qqbot:1905878837:群openid
```

绑定码固定私聊身份、AppID、群、已有对局、阵营与该席位实际群作者；只有相符的已验签群作者能消费。群友看到并抢发此码，也不能以自己的作者身份通过。有效期 300 秒，每个私聊身份最多 8 个未过期未使用码；过期后发一条新私聊消息重新申请。错误作者不消费，正确作者重复确认幂等，已有不同绑定不能被覆盖。绑定和业务收据持久化；群内确认回复不显示私聊身份。

这项绑定证明既有群席位持有人明确授权该 C2C 通道，不声称官方同账号身份兑换。公开 `union_openid` 文档是需特殊申请的频道关联应用能力，不是普通群成员到 C2C 的现成转换接口，见 [官方用户对象](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/channel/manage/user/model.md)。

服务层统一解析房间内绑定，因此 MCP 使用相同的已授权 C2C 固定身份也能操作原群席位。管理员在服务端 `IBS_AGENT_IDENTITIES` 中将独立随机令牌映射到已绑定 C2C，或来自已认证群事件的 member 身份；工具参数不接受身份或令牌，不用数字 QQ 号代替 OpenID。

SSH 启动器的 `IBS_MCP_BLUE_IDENTITY` / `IBS_MCP_RED_IDENTITY` 默认 `agent:blue` / `agent:red`。改为官方身份时，服务端须同时存在该身份对应的独立令牌映射。令牌只在服务器内部注入，不放本地 SSH MCP 配置。下面的 OpenID 是占位符：

```dotenv
IBS_MCP_BLUE_IDENTITY=qqbot:1905878837:c2c:USER_OPENID_A
IBS_MCP_RED_IDENTITY=qqbot:1905878837:c2c:USER_OPENID_B
```

默认两个 agent 也可在真实官方房间另建 PVP，再由群内「战况」查询公共图；它们不会自动拥有现有人类席位。实际权限仍由固定映射、显式绑定和游戏席位检查决定。

## 被动回复与输出上限

官方文档明确主动推送自 2025-04-21 停止。本实现只针对收到的消息被动回复：群消息 5 分钟内最多 5 次，C2C 60 分钟内最多 5 次。不继承旧 OneBot 的长期主动广播行为，见 [官方发送限制](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)。

文本按最多 1,500 字符分片，PNG 占一条回复。`/行动` 和 `/草稿` 已改为每页最多 6 项、1,400 字符以内的人类可读回复，不再发送整个合法行动/schema。其他高级 JSON 结果若完整输出超过 5 条，仍拒绝发送不完整 JSON；可通过 MCP 获取。操作可能已执行而回复受限，应重新查状态，不把未收到回复当成未提交。

游戏变更使用持久收据，重复事件不重复推进；官方回复分片/发送进度为进程内状态，重启可能重复一段回复，但不应重放游戏变更。单 worker、限时回复与失败处理不构成可靠的异步广播或离线通知承诺。

## 验证结果

安全绑定与既有服务 31 项通过；官方网关/工厂发现批次 36 项通过，增加连写命令及静态结果审计后 42 项通过。较早官方网关批次为 35 项通过，兼容批次 70 项通过，各批交叉覆盖不累加。真实引擎 MockTransport 联通测试与真实平台收据分别记录；实群目前已验证编队 PVE 建局、绑定、首次阶段推进、私聊本方图与群公共图的 API 投递，用户确认两处都有图。未据此宣称所有模式实群终局验收。

公开文档签名示例有单独保留的 1 项失败复现：公钥向量匹配，示例签名与所印正文不匹配。它不是产品真实回调失败；本 App 真实平台挑战已通过。GitHub 安全计数/失败测试名见 [批次摘要](evidence/validation-summary.json)，完整本地收据和未完成的群/C2C/LLM agent 终局见 [VALIDATION.md](VALIDATION.md)。

# Calendar-optimization benchmark protocol

Frozen before held-out results. All methods use identical physical payoff, public calendars, fixed opponent class and numeric tolerance. Optimization inputs include the physical game; no learned model or outcome-based parameter tuning is used.

Algorithms: complete calendar enumeration; calendar inclusion/exclusion branch-and-bound; the same search with full-response opponent-policy upper bounds; exact-increment greedy; uniform; front-loaded; back-loaded. Run budgets0..T−1, sharing exact calendar results WITHIN a method only. No other method's solved values or opponent policies enter a cold method run. Enumeration supplies the external reference frontier; comparing with it is validation, not an optimization input.

Response reuse: against C, each requested equilibrium supplies its complete committed-opponent distribution; against F, the requested empty-calendar equilibrium supplies a flexible opponent policy. No posterior observation, hidden suffix, or strategy from an unqueried calendar is supplied. Counterfactual response maximizes over all target-calendar policies. Reconstruction from a sequence-form solution preserves its realization distribution.

Two timing panels remain distinct:

1. All complete development/test conditions: online trace replay records requested calendar oracle calls and sums the individually recorded solver costs; response computations are actually executed. This is computational accounting, NOT observed end-to-end wall-clock speedup. On F cases without a recovered opponent policy, the response-bound variant has an empty pool and reduces to the base search; report this limitation instead of imputing acceleration.
2. Actual cold runs: predeclared head-on/parallel/crossing development speed1 distance16 and frozen-test first configuration speed.8 distance13.5, each against F/C. Recompute solver calls serially with an empty method cache; charge all initial pricing/fallback and response-bound costs. Load identical payoff before the timer; list its separate construction time. Restrict heavy computation to one process; figures label any resource-limited run rather than replacing it with trace time.

The experiment concerns complete budget frontiers, so report total distinct calendar calls and complete-frontier time, not cherry-picked fastest budgets. Baseline policies do not claim optimality. Same-precision interval regret is reported for every budget. Passing search correctness does not imply a speedup; full distributions, non-improvements and unresolved results stay visible.

Auxiliary inner-solver benchmark, fixed before the frozen test: the three robustness anchors at speed1,distance16,T4,Grid3,no ablation, all8 calendars and both opponent classes. Compare the complete sequence-form LP with the structured solver at the identical numeric threshold. Payoff construction is charged separately. Each cold inner solve has20minutes; each physical/opponent comparison has a6-hour cumulative cap. For the T6 complete-frontier cold benchmark, the same6-hour cumulative cap applies to the seven methods together in listed protocol order; incomplete later methods are retained with their resource reason and valid available bounds. This order is predetermined and can disadvantage later methods under a cap, which must be disclosed. Ordinary oracle calls retain the20-minute target.

Deletion-certificate and replay protocol: all development and frozen-test calendars enter the straight-shadow behavioral coarsening comparison. Use a full-update source optimized against the matched fixed opponent whenever available. Record any missing source and feasible fallback explicitly. On the frozen test, recover a policy for each distinct calendar selected anywhere on the budget frontier and evaluate its complete opponent response. Preserve the exact positive leaf-probability law. The illustrative leaf is the highest-probability leaf, with lexicographic ties, never selected for favorable payoff. Recovery time is reported separately from calendar optimization. Source generation plus all certificates/replays is bounded by6hours per physical instance and8GiB process-tree memory; missing outputs remain missing.

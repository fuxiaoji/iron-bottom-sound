# M2.2 → M2.4 研究弧线：整合报告（导师导读）

**一句话**：本轮把两个候选主线（联合战术编译 JTC、隐藏承诺下的信念感知拒止 BARD）都用**预先冻结的 cheap-kill 协议**做了裁决，结论是 **两条都不成立**——JTC 永久终止、BARD 归档；但过程中确立了三个可执行机制、一套双尺度（局部/队级）度量，以及一批**可发表的负面结论与诊断**。

**这不是一篇论文的初稿**，而是一次方法发现阶段的闭环记录。建议阅读顺序见文末。

## 2. 四个阶段的关键数字（全部 engine-exact，可追溯）

### M2.2：规则层有杠杆，但度量与编译器各有硬缺陷
- **同一冻结公式在两个尺度上给出相反答案**：舰队级手工舷射金标 **−12.17**，比随机合法计划均值 **−6.32** 还差；限制到该案例自身的舰对 **+1.89 > +1.44**（随机），保真度翻转为 GAP（SEARCH **+0.876**、CURRENT **−0.178**）。
- **仓库自带意图编译器把舷射意图转向反方向**（research-only 代码）：被告知 `BROADSIDE` 时给焦点舰的计划 `1S1P` 与**反向臂逐字符相同**（post_rel 5 / 1 个炮座，金标是 post_rel 1 / 3 个炮座）。
- **MG3 注册度量落在可交战包线之外**：2.56 vs 0.94 期望命中打在 15/17 格，而该状态盟军能见度 **13 格**、radar 规则 OFF → `_can_see = False`，引擎真实计量下两臂均为 **0.000**。历史 PASS 保留，但改注为 `EXECUTABLE_INVALID`，由新建的可执行 MG3-E 取代。
- **MG4 鱼雷走廊是全状态现象**：金标走廊精确复现（RouteReduction **0.966**、与引擎接触事件 12/12 一致），但可部署的公开信息搜索只有 **0.107**、当前 AI **0.000**。

### M2.2-R：双尺度分离后，问题变得可测
- **修复后的意图在局部赢、在队级输**：MG1 案例上 ΔL0 **+0.667**（41% 相对）而 ΔL1 **−5.833** → `MECHANISM_SUCCESS_BUT_NEGATIVE_EXTERNALITY`。**只有联合搜索两尺度都为正**（+0.472 / +7.417）。
- **MG3-E = PASS**：EM-01 s1 t10，两臂都在 13 格能见度内且各有 8 门主炮可用，9 格 **4.139** vs 12 格 **2.528**（相对 38.9%）。扫描 162 个状态、拒绝原因全部留档。
- **当前 AI 的鱼雷臂平均 RouteReduction = 0.000**（15 个状态里 6 个开火却零约束），公开臂 ≈0.010，全状态天花板 0.020–0.316。
- 自然普查中 beam 的负外部性率 **2.0%**，意图臂 12.9–16.5% —— 局部与队级不是同一个目标。

### M2.3：两个候选都不成立
- **JTC FAIL**：在**同一** 35 个机会状态上，联合 **1.048** < 逐舰贪心 **1.428** < 等预算随机 **1.831**。**并且我把混淆写进了判决正文**：M2.3 的廉价代理是逐舰可加的，所以逐舰贪心正是它的**精确最优解**，那个臂结构上无法检验协调——这直接导致 PI 批准了 M2.4 的最后一次重测。
- **BARD FAIL**：同公开历史信息集上冲突真实（11/14 有 best-action crossover、5/14 不存在 ε-good 共享动作），但 **size/diversity 匹配对照把 material 率从 0.357 砍到 0.214**，且只剩 **S-01 一个场景**；公开规划器只恢复天花板的 0.611 / 0.226 / 0.086，当前 AI 全 **0.000**。

### M2.4：交互是真的，但换不成收益
- **Gate I = PRESENT**：150 个舰对、全部 engine-exact，median |φ| 0.000 但 **p90 0.556**、**max 4.139**、**28% 舰对 ≥ 0.05**。并且用 engine-exact 的 q_i 拼出的**精确可加模型**对精确联合值的一致性只有 **0.037** —— 说明「加性描述不足」来自交互本身，不是代理粗糙。
- **Gate II = FAIL（六条预注册判据全否）**：主集 **6 胜 / 9 平 / 4 负**、win rate **0.316**、中位增益 **+0.000**、bootstrap CI [+0.000, +0.111]；逐场景 S-01 0.000 / S-03 **+0.222** / EM-01 **−4.194**。
- **最有信息量的一条**：`SEQUENTIAL_TEAM_BEST_RESPONSE`（逐舰依次移动、只接受精确改进）中位 0.000、CI **[−0.722, 0.000]** —— **显式建模 φ_ij 再据此搜索，并不优于最朴素的精确坐标上升**。可得协调收益已被后者吃掉。
- 这个 kill 不是预设的：修复臂内 bug 后首个状态 beam−greedy = **+0.972**，S-03 整场景中位 **+0.222**，符号在整面板跑完前是开放的。

## 4. 仍然站得住的科研资产（可写进论文的部分）

1. **三个 engine-exact 可执行机制**：舷射展开（MG1）、可执行距离控制（MG3-E，9 vs 12 格、38.9%）、鱼雷时空走廊（MG4，RouteReduction 0.966、与引擎接触事件 29/29 一致）。都带精确复现脚本与拒绝原因留档。
2. **局部意图保真与队级效用的系统性冲突**（L0/L1 双尺度 + 外部性定义）：在单案例、普查、以及重测三个阶段都出现，且方向一致——修复后的意图在局部 +41% 而在队级 −5.8 EH。
3. **「交互存在但不增值」的负面结论**：28% 舰对存在二阶交互、精确可加模型一致性仅 0.037，但显式利用交互的搜索在等预算下打不过逐舰精确坐标上升（n=19，6/9/4）。这是一个**有测量支撑的否定结果**。
4. **一套可复用的测量基础设施与陷阱清单**：FIRE_SEARCH 的七个保真要素（可见性 / 炮座单次 / 引擎修正 / 集火加成 / 分火惩罚 / 主副炮分组 / 批次验证）、size/diversity 匹配对照、paired bootstrap、真值/公开分离的规划器计分口径。
5. **BARD 指标集**（归档但可复用）：R_shared / R_Bayes（uniform 标签保留）/ best-action crossover / ε-good 共享动作判定，附两处使用陷阱。

## 6. 未做 / 不主张

- **未训练任何模型**（无 MAPPO/QMIX/GNN/Transformer），未改生产规则，未动生产引擎，0 付费 LLM 调用。
- **未做 L2（长视野对局价值）主张**；B1E 预注册即把 L2 留给后续阶段。
- **未做文献综述、未设计论文方法**；PI 原话是 cheap-kill PASS 之后才做 CCF-A closest-prior review。
- 不主张「规则引擎有问题」——恰好相反，三个机制的规则层定价都很陡；不主张「当前 AI 很弱」这种泛泛结论，只主张**逐状态测量的**具体差距（如鱼雷臂平均 RouteReduction = 0.000）。
- 不主张 JTC 的失败等于「协调无用」的普适结论；只主张**在本平台、本候选集、本次等预算下**，显式交互建模不优于逐舰精确爬山。

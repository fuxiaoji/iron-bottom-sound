### B.2 单位违规：模型仍在文里自己换算（实测 5 处）

同一句话重复 5 次（美方某编队）：

```text
「8-10海里」  ← 其接触表的 range_hex 是 8 与 10 格（约 2.8 与 3.6 海里）
```

引擎侧已把 `range_hex / range_yards / range_nmi` 一并交给模型（IR-6），
但**提示词里没有禁止换算的指令**，模型就按老习惯写了。本批次随后补上该指令
（编队与舰队提示词各一句：距离一律使用给定字段，12 格约 3.6 海里不是 12 海里），
并加了本局这 5 处的检测器——**但本局是在补指令之前跑的，因此本局的判定保持 FAIL**。
下一次实机对局应把这一项跑到 0；在此之前不宣称单位项通过。

### B.3 命令谱系：一个被测出的真实缺陷（已修 + 回归测试）

战报的命令修订表暴露出：**发给总指挥所在编队的每一条命令都是 `rev=1, amends=-`**，
且 T9 出现一条与 T8 完全相同的命令被接受。根因是**当面交办路径的次序错了**：

```python
if embarked:
    _apply_delivery(...)          # ← 先折入投递
    message.delivered_turn = turn # ← 后盖送达回合
```

`_apply_delivery` 用 `message.delivered_turn` 写 `order.confirmed_turn`，于是当面交办的命令
**永远未被"确认"** → 不进入"现行命令" → 去重与修订线都不生效（该编队整局都没有现行命令）。
修法：先盖送达回合再折入。回归测试
`test_a_face_to_face_order_is_confirmed_in_force_and_lineaged`（当面命令必须被确认、成为现行、
同文重发被拒、改文成为修订 2）。

**本局记录保留原样**（`rev=1` 与那 1 处重述是这一局真实发生过的历史）；
修复由测试证明，不由这一局的记录证明——记录不重写。

# 路由与延迟档案（v2.3）

本文件把命令延迟模式的**可达性参数**与**延迟来源**写成一份可核查的清单，
并标注每一项的出处类别（历史约束 / 仿真抽象），以免读者把抽象值当成实测值。

## 1. 可达性（决定用哪种媒介，不决定延迟）

| 参数 | 值 | 出处类别 | 说明 |
|---|---|---|---|
| 棋盘尺寸 | 46 × 39 hex | 想定数据 | S-01 与 EM-01 相同 |
| 棋盘最大合法六角距离 | **83 hex**（枚举全格对算得） | 实测 | 对角极端情形 |
| TBS 直连射程 `TBS_DIRECT_RANGE_HEX` | **73 hex** ≈ 25 法定英里 @ 600 yd/hex | 历史约束（近似） | 视距 VHF 语音，史料常见描述的量级 |
| 光学能见度（想定） | 13 / 15 hex | 想定数据 | 只用于"视觉信号能否用"，**不再当作无线电射程** |
| 本局实际报文距离 | 0–42 hex（均值 15） | 实测（`raw/old_message_route_audit.csv`） | 137/141 在 TBS 射程内 |

**记录在案的判断**：标准棋盘对角（83 hex）确实超出 73 hex 的 TBS 标称射程，
所以"距离永不相关"不成立；但本局全部报文都在射程内，v2.2 把**光学能见度**当无线电射程
才是产生 55 条虚假转报的根因（见 `01_COMM_ROUTE_AUDIT.md`）。

## 2. 媒介选择顺序（v2.3）

```text
同一指挥位置           -> FACE_TO_FACE（当面交办，非无线电事件，不占信道）
距离 ≤ TBS 射程        -> DIRECT_TBS（基础延迟 0）
有直视条件             -> BLINKER
有编码能力             -> WT_CODED
有**显式中继路径**     -> MULTI_HOP / 需密码域转换时 WT_REENCIPHER_RELAY
以上皆否               -> NO_PATH（BLACKOUT）
```

中继/再加密**必须**带 `route_nodes[]` + `why_relay_required`（再加密另需
`why_reencipher_required`），否则该路由非法（`RouteDecision.route_is_valid`）。

## 3. 延迟来源（每一项都必须落在报文的分解字段里）

```text
propagation   恒为 0（三个分钟一回合的尺度上，电磁传播在地图任何距离都等于零）
handling      拟稿/转录/分发（TBS 基础 0）
encoding      编码/发报/译码（编码电报基础 +1）
relay         每经过一个中继级 +1（需显式节点）
reencipher    每次密码体系转换 +1（需显式转换）
queue         有限信道容量造成的等待（由"实际耗时 − 其余分量"在送达时算出）
clarification 澄清往返（本模式当前为 0，字段保留）
```

**没有**任何"因为命令很长所以 +1"的规则：长度体现在**信道槽位**（≤240 字 1 槽、≤600 字 2 槽、
更长 3 槽），占不到槽位就在队列里等，延迟以 `queue` 分量出现。

## 4. 信道容量（仿真抽象）

| 媒介 | 每方每阶段槽位 |
|---|---|
| FACE_TO_FACE | 0（不占信道） |
| TBS 短距 | 4 |
| 视觉信号 | 3 |
| 编码电文 | 2 |
| 转报再加密 | 1 |
| 复合路由 | 1 |

容量按**阵营**分开：一方的通信量不会挤占另一方的信道。优先序 URGENT > OPERATIONAL > ROUTINE，
同级按发出回合与阶段序，超过 TTL（3 回合）丢弃并记原因。

## 5. 明确不属于本模式的东西

- 丢包率、错码率：**未定义**（`communications/integrity.py` 是显式的空操作接缝）。
- 国别差异：媒介选择里没有 `side` 参与；v2.2 观察到的"美方多用转报"是射程常量用错造成的副产品，
  v2.3 已消除（同一批报文重算：转报 55 → 0）。

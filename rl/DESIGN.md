# 状态机 AI 遗传训练 —— 设计文档

> 用途：讲解「现在怎么训练的」，供后续复现/改参/审查。实现见 `evolve.py`，
> 命令速查见 `README.md`，实时面板见 `watch.py`，稳健性验证见 `verify.py`。

---

## 通俗版（30 秒读懂）

用遗传算法进化 `TacticalCommander` 的 16 个策略权重：

1. **配方**：每个候选 = 16 个"旋钮"（多想冲？多怕打？多爱放雷？…）组成的一种打法。
2. **打擂台**：每张配方下场打比赛 —— 双想定 × 当轴心/盟军 × 对手池（均衡/大舰队/乱战…）
   各打 N 局，看总胜率。
3. **配种**：优胜劣汰 —— 好配方留下，两两交叉混出新配方 + 随手变异（拧几个旋钮），
   新一代再上场。
4. **保多样**：只按胜率选会收敛成一种打法，遇到克星团灭 → 额外奖励"打法不一样"的个体
   （新奇度），让群里既有敢冲的也有猥琐的。
5. **别信运气**：单局像抛硬币（~50/50）。终局对前几名再打一大轮（24 局/槽）选最稳的当
   **冠军**。
6. **出山考试**：冠军换全新开局打 6 种对手，确认真比手调均衡强，才交付给 BC 当老师。

每"一代"= 全员打擂台 → 记分 → 配种变异 → 新的一代，反复 5~10 代。

## 0. 为什么用遗传算法训状态机 AI

目标：做 **BC（行为克隆）** 之前，先把要被克隆的老师 —— `TacticalCommander` 的
`TacticalProfile` 权重 —— 从"手调默认"进化成"比手调更强"。BC 再用老师产监督数据。

为什么不直接手调 / 搜索？因为 16 个连续权重 + 阈值构成的高维空间没有解析梯度，
只能通过**打对局**估分。GA 适合：评估器黑盒、噪声大、要保留打法多样性。

**治理纪律（硬约束）**：引擎唯一裁决。训练只读用 `run_match`，不碰状态、不改裁决、
不复制规则常量到引擎外；RL 层任何异常不影响对局（`_run_one_game` 兜底为 error 记录）。

## 1. 训练对象：TacticalProfile → 基因组

`TacticalProfile`（backend `tactical.py:29-73`）是一组启发式权重/阈值。进化的
**16 个连续基因**（`evolve.py GENE_SPECS`）：

| 基因 | 范围 | 默认 | 含义 |
|---|---|---|---|
| `w_enemy_heat` | 0–4 | 1.0 | 对敌火力热度的权重 |
| `w_fire_pressure` | 0–4 | 1.0 | 受敌方火力压制（威胁）权重 |
| `w_approach` | −2–3 | 0.5 | 主动逼近对手的权重 |
| `w_formation` | −2–4 | 0.0 | 保持编队的权重（负=更自由） |
| `line_ahead` | −2–4 | 0.0 | 纵队队形偏好 |
| `w_predict_opponent` | 0–2 | 1.0 | 预判对手动向的权重 |
| `w_retreat` | 0–3 | 1.0 | 受损撤退权重 |
| `w_protect_own` | 0–3 | 0.5 | 保护己方舰权重 |
| `w_vp` | 0–3 | 0.3 | 争夺胜利点权重 |
| `w_finish` | 0–3 | 0.5 | 残血收人头权重 |
| `w_self_status` | 0–3 | 0.3 | 自舰状态权重 |
| `torpedo_min_expected` | 0–0.8 | 0.30 | 鱼雷最低预期命中 |
| `retreat_hull_threshold` | 0.1–0.7 | 0.35 | 撤退血量阈值 |
| `temperature` | 0–1.5 | 0.5 | 决策软采样温度（0=贪心） |
| `approach_range` | 6–24 (**整**) | 12 | 逼近开火距离 |
| `torpedo_max_range` | 6–20 (**整**) | 10 | 鱼雷最大射程 |

- 结构字段（`formation_spacing` / `top_k_candidates` / `rng_seed_off`）不进化，保持默认。
- `encode_profile` / `decode_genes`：基因 ↔ `TacticalProfile`；解码时逐基因 clamp、整数取整。
- 内置 6 风格（balanced/fleet/line/brawl/torpedo/cautious）作为初始种群起点。

## 2. 适应度：怎么给一个基因组打分

### 2.1 评估对象（槽位矩阵）

一个个体要打：

```
想定 (IBS-S-03 + IBS-S-01) × 对手池 (balanced,fleet,brawl) × 双阵营 (axis/allies) × games_per_opp 局
```

- **双想定都打**：两想定共用同一主图（34×27），一套权重必须对两个想定都成立 →
  直接度量"跨想定复用"。
- **双阵营都打**：个体同时作轴心和盟军，抵消阵营不对称（axis 侧有固有微弱优势）。
- **固定开局集**：seed 按 `seed_base + scen*7 + ind_id*1009 + opp_idx*101 + k` 派生，
  同代内每个个体看同一批开局（比较噪声小），不同个体开局不同（防全群过拟合同批）。

### 2.2 每局打分

`_run_one_game` → `run_match(axis=tactical, allies=tactical, 各自 profile=decode(genes), seed)`。
返回 winner / 双方 VP / completed / elapsed_ms；异常兜底为 `error` 行。

### 2.3 聚合 → fitness

```
score_sum   = Σ (+1 胜 / −1 负 / 0 平)
margin_sum  = Σ 己方VP − 敌方VP（按视角）
win_rate    = score_sum / 总局数          ← 胜−负差分，范围 [−1,+1]
avg_margin  = margin_sum / 总局数
fitness     = win_rate + 0.01 × avg_margin   ← 0.01 是 vp_weight
```

**注意**：GA 内部排序用的是**胜−负差分**（不是 0~1 胜率）；面板 `watch.py` 显示的是
**真实胜率**（胜局/总局数，0~1），两者含义不同，别混。

### 2.4 噪声问题（实测教训）

S-03/S-01 的对局结果近似伯努利 ~50/50：**单局方差 ≈ 0.5**，`n` 局槽位的噪声
std ≈ `1/√n`。小规模（4 局/槽）实测：某个体的 8/8 全胜（fitness +1.0）只是运气，
fresh seed 一验就打回原形（vs balanced 只有 +0.083 噪声级）。→ 解决：
① 中规模提高局数；② **冠军复评**（见 §6）。

### 2.5 评估标准：相对 vs 绝对（关键概念）

**相对数据**（目前所有胜率/VP 差）：都是"**对谁打出来的**"。对手池换一批，数字就变。
对弈类评估的本质决定——没有对手，"强弱"无法定义（国际象棋 Elo 也是锚定 1500 的相对刻度）。

**引擎里真正"绝对"的锚点 = 胜负判定本身**（引擎唯一裁决，engine.py:3208-3238）：

- **S-03 不是比分数**，而是比"达成剧本目标没有"：
  - 英军战略/战术胜利 = 击沉或减速 ≥1 艘德舰（达成进攻目标）
  - 德军小型战略胜利 = 击沉 ≥2 艘英舰（达成目标）
  - 德军战术胜利 = **默认兜底**（只是对方没达成目标，不等于德军干成了事）
- **S-01** = 胜利点差 ≥4 判胜，否则平局。

**绝对标准落地**（`_run_one_game` 已记录 `victory_reason`；`verify.py` 输出）：
- **目标达成率**：个体作为轴心，有多少局真的"击沉 2 艘英舰"；作为盟军，有多少局真的
  "击沉/减速德舰"——锚在游戏规则，而非某个 AI 对手。
- **Elo vs balanced 锚点**：以手调 balanced 为固定锚（=1500），ΔElo = 400·log10(S/(1−S))，
  把"相对胜率"转成可跨实验累积的**绝对刻度**（正 = 比手调均衡强）。
- 两者配合：相对胜率看"打得过谁"，绝对刻度看"强度多少"，目标达成率看"赢是干成的还是白捡的"。

实测例（verify 冒烟）：某 best 轴心胜率 0.0（2/4 全走默认兜底），但**轴心目标达成率 0%**
——它从来没真击沉过 2 艘英舰。这就是"赢"和"达成目标"的差别，只看相对胜率会误判。

## 3. 选择 / 交叉 / 变异（GA 循环）

### 3.1 初始种群 `_init_population`

按序塞入 6 个内置风格（保底多样性），其余：70% 围绕随机内置风格**高斯抖动**
（σ=区间宽度×(0.05~0.25)），30% 完全随机，去重。

### 3.2 每代流程

1. 评估全群体（§2）
2. 算行为描述子 + 新奇度（§3.4）
3. 精英保留（top `elite_fraction=15%`，原样复制）+ 名人堂更新（跨代全局最优，
   存 `hall_of_fame=4` 个不同基因组）
4. 繁殖下一代到 pop_size：
   - **锦标赛选择**（`tournament_k=3`，按 `adjusted_fitness`）
   - 80% 概率**交叉**（§3.3），否则克隆单一父本
   - 对子代**变异**（§3.3）
   - 精英 + 名人堂成员直接进入下一代（不交叉不变异）

### 3.3 交叉与变异（多样性核心）

- **交叉**：
  - 30% 概率**均匀交叉**（逐基因随机取父/母）；
  - 70% 概率 **BLX-α**：`child ∈ [min−α·d, max+α·d]`，α=0.5 —— 向父母区间**之外**
    外推，自然产生区间外新基因（防止收敛到父母区间内）。
- **变异**（随代数衰减，progress = gen/(gens−1)）：
  - 逐基因高斯噪声：概率 `0.40 → 0.15`，σ = 区间宽度 × `0.20 → 0.05`
    （前期多探索，后期小步精修）；
  - 3% 概率**整基因重置**（跳回均匀区间）→ 防止早熟收敛的多样性注入。

### 3.4 新奇度（Novelty Search）

- **行为描述子** = 个体在「想定 × 对手 × 阵营」各槽位的胜率向量（直接度量"打法长啥样"）。
- **新奇度** = 描述子到 k 近邻（k=3）的 L2 距离。
- `adjusted_fitness = fitness + 0.5 × novelty` —— 选择直接奖励"打法不同"的个体。

## 4. 冠军复评（去噪声，交付 profile 的最后一环）

逐代 fitness 局数少、噪声大，**不能**直接拿逐代最优当交付。终局做：

1. 取名人堂 top-4 基因组；
2. 每人打 `champion_games=24` 局/槽（× 双想定 × 对手池 × 双阵营，
   用与训练/验证**全不相交**的 seed 基 `champion_seed_base=70000`）；
3. 按复评胜率 + VP 差排序 → `champion-genome.json` / `champion-profile.json`。

→ 交付的是"大量局数下真正稳健"的最优，不是噪声尖峰。

---

## 5. 验证（fresh seed 防过拟合）

`verify.py` 用**全新的 seed 基（50000）**在双想定 × 6 对手 × 12 局/槽上重测
`champion-genome.json`，输出逐槽胜率/VP 差 + 跨想定 combined；可选 `--baseline`
跑 balanced-vs-balanced 同 seed 基线做语境。目的：回答"它到底是不是比手调强"。

## 6. 完整流水线（一图流）

```
6 内置风格 ──► 初始种群(32)
                 │ 每代：
                 ▼
   [评估] 想定×对手×阵营×seed 全部对局（20 进程，submit+as_completed 流式落盘 games.jsonl）
                 │
                 ▼
   [聚合] 每槽胜率 → 描述子 → 新奇度 → fitness = 差分 + 0.01·VP差 + 0.5·novelty
                 │
                 ▼
   [选择/繁殖] 精英15% + 名人堂4 + 锦标赛(3)选父母 → BLX-α/均匀交叉 → 高斯变异
                 │  ←── 回到 [评估]，迭代 gens 代
                 ▼
   [冠军复评] 名人堂 top-4 × 24局/槽 → champion-genome/profile.json（交付）
                 │
                 ▼
   [验证] verify.py fresh seed 双想定 × 6 对手 → 对照表（是否优于手调 balanced）
```

## 7. 并行与实时

- **多进程**（`ProcessPoolExecutor`）：纯 Python 引擎受 GIL 限制，多线程无加速，
  多进程才有真并行。`workers=20` 用满 32 逻辑核。
- **流式落盘**：`submit + as_completed`，每局完成**立刻**写 `games.jsonl` 并 flush
  （不是每代攒一批）。→ `watch.py` 面板能实时看到胜率爬升。
- **GPU 无收益**：状态机对局是纯 Python 引擎，GPU 留给后续 BC/PPO 神经网络。

## 10. 当前进度与已知结论

- **v0 小规模**（S-03 单想定，pop16，8 进程，10 代）：机器全通、无多样性塌缩
  （unique=16/16，基因距离 1.105→1.347 上升）；但暴露**评估噪声**——best 训练 seed
  上 8/8 全胜，fresh seed 验证并不优于手调 balanced。
- **v0.5**：双想定 + 冠军复评去噪 + 流式落盘 + 实时面板 + 双想定验证。
- **v1 中规模 5 代**（已完成，`rl/results/ga-dual-med-v1`）：pop32 × 3 对手 ×
  8局/槽 × 双想定 × 20 进程，墙钟 3679.8s（~61 分钟）。收敛：best fitness
  +0.123→+0.212，mean −0.096→−0.038；**多样性无塌缩**（unique=32/32 全程、
  基因平均距离 1.147→1.483、novelty ~1.7）。
- **v1 冠军**：冠军复评（4 候选 × 288 局）最优 cand0 = 胜率差分 +0.094、
  均 VP 差 +0.14。16 基因全部偏离默认（w_enemy_heat=2.51、w_retreat=3.0 封顶、
  w_approach=−0.45、w_vp=1.36）→ 风格："热点集火 + 拒绝逼近 + 高撤退 + 抢 VP"
  的防守反击型。fresh-seed 验证（verify.py）：跨想定 combined +0.066，
  **Elo vs balanced 锚 = +36**（略强于手调均衡）。
- **⚠ 诚实结论（v1 验证）**：
  - S-03 盟军目标达成率 **55.6%**（过半对局真击沉/减速德舰）——盟军侧是"干成事"的赢。
  - S-03 轴心目标达成率 **0%**——轴心从不真击沉 2 艘英舰，轴心赢全靠**默认兜底**
    （德军战术胜利 = 英军没达成目标）。GA 找到了 S-03 规则漏洞：防守不死 = 白捡胜利，
    因为对手也是防守型状态机。
  - S-01 无目标判定（VP 差≥4），轴心明显偏弱（combined 轴心 −0.111 / 盟军 +0.264）。
  - 结论：**冠军比手调 balanced 略强但幅度很小**（+36 Elo 是弱正信号），且"强"里
    掺着规则兜底。BC 用此冠军做老师可行，但若想真达成剧本目标，需要**奖励目标达成**
    或更强的对手池逼出进攻性。
- **S-01 风格混战赛**（style_tourney.py，7 风格 × 12局/槽 × 双阵营 = 1008 局，
  fresh seed，`rl/results/style-tourney-s01`）：
  - **S-01 想定结构决定两边胜率**：盟军开局占点领先、轴心第 3 回合增援——**所有风格**
    当轴心都是负（−0.24~−0.36），当盟军都是正（+0.06~+0.43）；平局率 ~60%（胜利点差<4）。
    轴心弱是**想定侧固有劣势**，不是某个风格的问题。
  - **风格排名（combined）**：torpedo +0.062 > balanced +0.042 > fleet ≈ champion −0.007
    > brawl −0.049 > cautious −0.055 > **line −0.152**。盟军侧 torpedo 最强
    （决定性 34:3，均 VP 差 +3.06）——高接近 + 远射程鱼雷在抢 VP 的想定里最会"得分"；
    line（僵硬纵队）最差——队形刚性在无明确目标的 VP 局里是累赘。
  - **冠军在 S-01**：mid-pack。当轴心**流血最少**（均 VP 差 −1.42，全场最低），当盟军
    决定性 24:8 不错；专吃 line（+0.292）和 brawl（+0.083），怕 torpedo/fleet/cautious。
    冠军的防守型打法在 S-01 里"能守但不太会赢"，印证它不进攻的基因特征。
- **已上线游戏（7 风格对手阵容，2026-08-26）**：后端新增 `champions.py` 注册表
  （`CHAMPIONS["evolved"]` = 全局进化冠军，代码常量自包含），`match.py make_session` 与
  `api.py ai-opponent` 均接受 `PROFILES | CHAMPIONS` 名称；前端 `App.tsx` `AI_PROFILES`
  分两组（内置风格 6 + 进化冠军 1）展示，每项带简介 + 胜率标注。胜率取自
  `rl/results/style-tourney-final`（7 profile × 双想定 × 12 局/槽，288 局/风格）：
  - **双想定综合胜率差分**：balanced **+0.018** · fleet +0.017 · brawl +0.007 ·
    torpedo +0.003 · line −0.073 · **evolved −0.077** · cautious −0.145。
  - **⚠ 重要诚实结论**：进化冠军在 7 阵容**全体互殴**里排**倒数第二**（此前 +36 Elo 只对
    balanced 单独有效）；两想定轴心侧全负（想定侧固有劣势），S-03 全无平局（目标制）、
    S-01 平局 ~60%（胜利点差<4）。**"进化冠军"的价值是打法个性（防守反击），不是更强**——
    标注与实际对局表现一致。若想要各风格独立的进化冠军，需再跑 6 场风格锚定 GA。
